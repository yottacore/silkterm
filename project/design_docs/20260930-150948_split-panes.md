## Summary

A tab can be split into panes, each running its own shell. Splits are made from the Panes menu, the right-click menu, hotkeys, or the command line, resized by dragging the divider, and swapped by dragging a pane. Hotkeys also close a pane and move between panes. A new pane starts where the pane it came from was, with the same shell.

## Specification

- A window is a list of tabs, and a tab is a tree of panes. Every split divides one pane in two, side by side or one above the other.

- Splits come from the Panes menu, the right-click menu, hotkeys, and the command line. As in Windows Terminal, Alt+Shift+Plus splits right, Alt+Shift+Minus splits down, Alt+Shift+W closes the pane, and Alt+arrows move between panes. On macOS, as in iTerm2, Command+D splits right, Command+Shift+D splits down, and Command+Option+arrows move. Option+Command+W closes the pane, because Command+W closes the tab. Each can be changed or turned off under `keys:` in the config file, or on the Settings dialog's Keys tab.

- Focus follows a click, or a move by hotkey to the pane in that direction.

- A new pane starts in the current directory of the pane it split, running the same shell. The same goes for a new tab or window made from a pane.

- Splitting the same way again and again shares the space evenly, so the panes go to halves, then thirds, then quarters. Once a divider in that run is dragged by hand, later splits there go 50/50 and the dragged sizes are kept. A split in another direction, or of another pane, starts its own run.

- Dragging the gap between 2 panes resizes them. Neither side can be squeezed away. The pointer changes to a resize cursor over a divider.

- Shift plus a left press grabs a pane. The pane under the pointer is tinted as the target, and releasing the button swaps the 2 panes.

- The focused pane has a ring around it, but only when the tab has more than one pane.

- A pane is at least 2 columns wide.

- Closing a pane closes only that pane. Closing the last pane closes the tab, and closing the last tab closes the window. A shell that exits closes its pane the same way.

- On close, the program in the pane gets a quarter of a second, and is then left to finish on its own. It's never killed.

- Each pane has its own scrollback, scroll position, selection, and scrim.

- A drag selection stays in the pane it started in, even if the pointer crosses into a neighbor.

- A pane in a tab that isn't shown doesn't draw anything, and catches up in one cut when its tab is shown.

- From the command line, a layout is a list of tabs and panes with create and select options, and settings cascade from the window to the tab to the pane. See the [Command-line options](../design.md#command-line-options) section of `design.md` and the done backlog item "Command-line options:" for the full option list.

## Goals

- Several shells side by side, laid out with the mouse or from one command line.

- A new pane that picks up where the work is, rather than in the home folder.

- A layout that stays even without fiddling, and stays put once it has been adjusted by hand.

### Non-goals

- A different font, colors, or wallpaper per pane. All panes in a window share one text context.

## Design

### The split tree

- Each tab has a `PaneManager`, which is a binary split tree of `Node::Split` and `Leaf`. A leaf is a pane with its layout rectangle, selection, and state. Each pane wraps one terminal instance, with its own reader thread.

- Every split has a ratio. A divider drag sets that ratio from the pointer, clamped so neither side can be squeezed away.

- The gap between panes and its grab zone are in DIP, so they're the same physical size at any display scale. The gap doesn't round down to zero on a screen scaled below 1x. The divider slits keep their own color rather than a tint from the wallpaper.

- Pane IDs come from one program-wide counter, so an ID never repeats across tabs.

- Closing is one function that walks pane, then tab, then window, in the tab that owns the pane. It acts only on the pane its menu was opened for.

### Evening out a run

A run is a sequence of splits in the same direction, from the same ancestry. A new split in a run that doesn't have its own size shares the space equally with the others. A divider dragged by hand marks the run as sized by hand, and from then on a new split there goes 50/50 and leaves the rest alone. A split in another direction or ancestry starts its own run.

Keyboard, menu, and command-line splits go through the same placing code. A command-line split with a size keeps it, and marks its run as sized by hand, the same as a drag.

### Direction

- A command-line pane without a direction takes the direction given to the pane it splits, and passes it on, so a run of panes stacks the same way.

- If there isn't a direction to take, the split goes along the pane's longer side.

### Where a new pane starts

- A new pane, tab, or window starts in the source pane's current directory, with the same shell.

- The directory comes first from what the shell last reported through OSC 7 or OSC 9;9, and then from what the OS can see of the shell's process. On Windows the OS doesn't have a call that returns another process's directory, so it's read from the shell's own process memory. A report that no longer names a directory on this machine is dropped.

- The Tabs and Panes menus have "Split with shell" flyouts, to start the new pane in another shell. It still starts in the source pane's directory.

- `--directory` on the command line cascades from window to tab to pane, exactly as `--shell` does.

### Focus and input

- Focus follows a click. The focused pane of the focused window is the only one with a live cursor animation and the only one that copies on output.

- A focus move by hotkey goes to the nearest pane that way that shares some of the focused pane's edge. When several are the same distance away, the pane the last move came from wins, so a move and its opposite go back and forth. After that, the top or left one wins. A move doesn't wrap around.

- A split or close by hotkey runs the same code as the Panes menu row, on the focused pane, and the row shows the chord.

- On Linux and Windows the pane chords are no longer passed to the shell. That costs fish its Alt+Left and Alt+Right (directory history, or word moves on a typed line) and Alt+Up and Alt+Down (history search), tmux its prefix plus Alt+arrows (pane resize), nano its Alt+Up and Alt+Down (scroll by a line), emacs its Meta+Left and Meta+Right (word moves) and Meta+Shift+W (copy, as Meta+W), and readline its Meta+_ (last argument, which Meta+. still does). Readline's word moves are Alt+b and Alt+f and stay free, and vim doesn't use any of these by default. Turning a hotkey off under `keys:` gives its chord back. On macOS nothing is lost, because Command is never passed to the shell.

- A left press on a divider starts a resize rather than a selection.

- A drag that leaves its pane keeps selecting in the pane it started in, and a pointer outside the pane is pulled to the nearest edge cell. See the [Double-click and selection](20260930-151047_double-click-selection.md) design doc.

### Drawing per pane

- The scrim is clipped per side. It's clipped to the content edge at an inside divider, and to the pane edge at the window border.

- Fallback glyphs are clipped to the pane's content.

- The wallpaper pass writes each pane's fill itself, clipped to the pane.

## Alternative ideas

### Unconsidered

- "Save entire current layout to config" on the File menu. It would write the layout as the command line's create and select options, with explicit directions and sizes so it reproduces at any window size, or as nested blocks. Backlog: "Additional "File" menu option: "Save entire current layout to config"" (Opened 20260628-083740).

### Rejected

- A terse `--layout` string, such as `'(.|.)-. ; nvim|{git log}'`, as shorthand for the create and select options. It was canceled, and no reason was recorded. Backlog: "Terse `--layout` DSL as optional sugar over the window/tab/pane CLI model" (canceled 20260713-142351).

### Superseded

- No hotkeys for splitting, closing, or moving between panes, so the chords shells bind stayed free. Panes take Alt+Shift chords and Alt+arrows now, as Windows Terminal does, and any hotkey can be turned off in the config file. Backlog: "No hotkeys for pane management except" (closed 20260629-214404) and "Hotkeys for splitting panes and moving between them, and menus that show the hotkey they share" (2026100220292607).

- A command-line split without a direction always going along the longer side, and always at 0.5. Direction is now passed down the split chain, and a run without sizes is evened out. Backlog: "A command-line split does not reuse the direction of the pane it splits" (2026092621021531).

- A typed `exit` in a tab closing the whole program. It closes the pane, then the tab, then the window. Backlog: "High severity: Typing "exit" in tab, closes the whole application".

## Research findings

- Once direction and evening out were fixed, 3 command-line splits down came out 15 rows each, and 3 to the right gave 4 panes of 29 columns each.

## Roadmap

- A font, colors, and wallpaper per pane, and a per-pane font size. They all need a renderer per pane. Backlog: "Command-line options:" (Opened 20260628-083740) and "Hotkeys to increase and decrease font size".

- A per-pane `--title`. It's accepted and reserved, but nothing shows it yet. Same backlog item.

- When stacked tmux panes print at once, only one slides. See the [Smooth scrolling](20260930-144720_smooth-scrolling.md) design doc.
