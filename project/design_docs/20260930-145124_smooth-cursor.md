## Summary

The cursor slides along the line as text is typed, and it pulses or fades instead of blinking on and off. The animation rests while someone is typing, stops for good when nobody has touched the terminal for a while, and costs nothing while it is parked. Only the focused pane of the active window animates.

## Specification

- The cursor slides to its new column as text is typed or edited. A move to another line is instant.

- When the cursor falls behind, for example during a paste, it speeds up. It is never more than a few cells behind.

- The cursor's size is two percentages of the cell: width from the left and height from the bottom. The default is a full block.

- The animation is one of five styles: none, a fade, or a pulse that grows and shrinks up and down, side to side, or both. The default is the up-and-down pulse. One cycle takes the blink rate, 500 ms by default.

- Typing pauses the animation.
	- The cycle is allowed to finish growing to full size, then stays there.
	- It starts again from full size once typing has stopped for the inactivity timer, one second by default.
	- The size never jumps, not when the pause starts and not when it ends.

- Output from a program pauses the cursor only while the output is being written. When the prompt comes back, the animation starts again with no delay.

- Focusing the window again, or moving to another tab or pane, restarts the animation at once, from full size.

- After 60 seconds with no typing and no refocus, the animation stops, parked at full size. Output from a program does not count as activity here.

- Only the focused pane of the active window animates. Every other cursor is parked at full size.

- A parked cursor draws no frames.

- A program that hides the cursor gets no cursor drawn at all.

- The character under a block cursor must be readable in every theme, in dark and light mode.

- The cursor can join the text scrim and the text outline. By default it joins the outline and not the scrim.

## Goals

- A cursor that moves the way the text around it moves: smoothly, and never with a jump in size or place.

- A clear signal of where typing will go, without a hard on-off blink.

- No cost while nothing is happening. An idle terminal on a laptop should not keep a core busy to animate a cursor.

### Non-goals

- Changing how the shell edits a line. Insert and overwrite belong to the shell's line editor, and a terminal cannot force them.

- Settings for the slide itself. Its speed and catch-up are source constants.

## Design

### The slide

The cursor slides toward its target column with an exponential ease. A newline snaps it, so a slide never runs diagonally across the screen.

- The time constant shrinks the farther the cursor trails, so a paste or a fast burst catches up while a single-cell move keeps the gentle slide.

- A hard cap keeps the drawn cursor at most eight cells behind its real column.

- The animation keeps running through the slide. An earlier version drew the cursor as a solid full block while it slid, which made its size jump on every keystroke.

### Shape and animation

- `cursor.size.width` is the width in percent from the left. `cursor.size.height` is the height in percent from the bottom. A bar is about 15 wide, and a block or underline is 100 wide. Together they make any shape, which replaced an older shape setting.

- `cursor.animation` is `none`, `phase`, `pulse_vertical`, `pulse_horizontal` or `pulse_both`.
	- `phase` is a smooth cosine fade between on and off.
	- A pulse starts as a single-pixel line in the middle of the cell, grows to full size, stays there a moment, shrinks back and disappears for a moment, then starts again.
	- Every style fits one cycle into `cursor.blink_rate_ms`.

- Frames that only change the cursor skip reshaping the text, so an animating cursor does not peg the CPU.

### Pausing and parking

The machine is `PauseState` in `pane.rs`. Its rule is the part that took several attempts to get right: a pause always waits for the largest point in the cycle, and a resume always starts from that same point.

- Typing pauses the cursor. Input lets the cycle run on at normal speed until it reaches full size, and it stays there. It resumes from full once typing has stopped for `cursor.animation_resume_s`.

- A keystroke's echo counts as typing, but only if it comes right after the key. Anything later is the program's own doing. So pressing Enter does not class a whole build's worth of output as typing.

- Output parks the cursor only while it is being written. When it stops, the animation picks up with no delay.

- A refocus of the window, tab or pane resumes at once from the top of the cycle.

- The long stop is measured from the last input or refocus, not from the last time the cursor moved. A clock in a prompt, or any full-screen program on its own timer, moves the cursor every few seconds and must not keep it animating. `cursor.animation_idle_stop_s` is 60 by default, and 0 means never.

- Every pane other than the focused pane of the active window is parked, through the same machine.

- A parked cursor draws no frames. Parked idle is about 0.2% of a core, against about 14% with the pulse running. An unfocused window's panes all park, so no frames flow at all.

- The old always-animating mode is behind the source constant `CURSOR_ANIM_CONTINUOUS`. `FREEZE_UNFOCUSED_BLINK` rolls back the parking of unfocused panes.

### Waking on time

A parked cursor that is due to resume sets its wake time while the frame is drawn. The event loop reads every pane's wake, the cursor's and the minimap's, from one list after the frame, not before it. Reading them before drawing left a cursor that parked during the frame with no wake at all, so it waited for some unrelated event.

### Hidden cursors

Whether the cursor is shown and what shape it has are two separate things in the engine, and both are read. A program that redraws its whole display hides the cursor first, redraws, then puts it back and shows it again. Reading only the shape drew a second cursor wherever the redraw left it, which on Windows is the bottom-right corner. A hidden cursor is not drawn and costs no frames.

### Drawing order and legibility

- The cursor is drawn after the scrim is composited and under the crisp text, so the scrim never covers it.

- The cursor draws into the scrim's source before the blur when `cursor.scrim` is on, so its halo costs nothing extra. `cursor.outline` works the same way for the outline.

- A block cursor is a second background. It is drawn as a plate under the glyph, and the glyph keeps its own color, so the text on it has to clear the contrast floor against the plate. See the [Themes](20260930-150458_themes.md) design doc for the plate's strength in light and dark mode, and for the cursor colors.

## Alternative ideas

### Unconsidered

- Smooth vertical cursor movement. Only the horizontal slide exists. Raised in "The Notorious "Bouncing Shadow in Wobbly Nano" bug" (Opened 20260707-182523).

- A gold pulse from the cursor when a command returns to the prompt, stronger the longer the command ran. It is Effect 2 of "Rolling epic "GPU FX"" (Opened 20260714-091630).

### Rejected

- Insert and overwrite modes with a cursor for each. A terminal cannot put the shell's line editor into overwrite mode. Backlog: "Allow toggling from default "Insert" mode, to "Overwrite"" (canceled).

- A lower frame rate for the idle cursor. 30 frames a second is the floor for smooth motion. Parking the cursor solved the cost instead. Backlog: "Epic 1n6fydv: Reduce CPU and GPU resource usage", item 2.3.

- Freezing inactive windows unless they have output. Folded into parking the unfocused panes, since a visible window with output should keep drawing. Same epic.

### Superseded

- `cursor_animation_input` with a "continuous" mode that never paused. Pause is the only mode now. Backlog: "Cursor animation immediately resets and starts over on keypresses" (Opened 20260703-211333).

- A two-second wait before resuming after typing. It is one second now. Backlog: "Cursor animation pause: one second, and no wait at all on refocus".

- A fade (`phase`) as the default animation, then a 25%-wide bar as the default shape. The defaults are the up-and-down pulse and a full block. Backlog: "Cursor: new defaults for size and animation" and "New defaults: block cursor, and wallpaper rotation on by default".

- The `cursor_shape` setting. Width and height percentages replaced it. Backlog: "Cursor settings: size as two percentages, plus an animation style".

- Cursor colors #ff88aa, then #eecc88 on #88eecc text. Both read badly under the cursor. See the [Themes](20260930-150458_themes.md) design doc.

## Research findings

- The cursor animation was the largest idle cost in the program. A running pulse took about 14% of a core, and about 6% focused against about 0% unfocused after parking.

- A program that moved the cursor every 2.5 seconds kept the old animation running for as long as it ran, since the stop was measured from cursor movement.

## Roadmap

- The three "Animation pauses on" checkboxes planned for the Cursor tab: loss of window focus, loss of pane activity and input inactivity. The first two are source constants today. Backlog: "Settings dialog" (Opened 20260719-085918).

- A per-program list that turns the cursor animation off while that program runs. It could be done per pane. Backlog: "Config file: For each feature listed below, allow user to list programs" (deferred, Opened 20260708-115155).

- The four window-level wakes read after the frame have no test yet, and a cursor resuming on time needs a look on screen. Backlog: "A cursor blink or fade can wait for an unrelated event" (2026092821452948).
