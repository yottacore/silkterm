## Summary

The cursor slides along the line as text is typed, and it pulses or fades instead of blinking on and off. The animation pauses while someone is typing, and it stops for good when the terminal hasn't been touched for a while. It doesn't cost anything while it's parked. Only the focused pane of the active window animates.

## Specification

- The cursor slides to its new column as text is typed or edited. A move to another line is instant.

- When the cursor falls behind, for example during a paste, it speeds up. It's never more than a few cells behind.

- The cursor's size is 2 percentages of the cell. One is the width from the left, and the other is the height from the bottom. The default is a full block.

- There are 5 animation styles. They're none, a fade, or a pulse that grows and shrinks up and down, side to side, or both. The default is the up-and-down pulse. One cycle takes the blink rate, from one peak to the next, 1000 ms by default.

- Typing pauses the animation.
	- The cycle is allowed to finish growing to full size, and then the cursor stays there.
	- It starts again from full size once typing has stopped for the inactivity timer, 1 second by default.
	- The size never jumps, either when the pause starts or when it ends.

- Output from a program pauses the cursor only while the output is being written. When the prompt comes back, the animation starts again without any delay.

- Focusing the window again, or moving to another tab or pane, restarts the animation at once, from full size.

- After 60 seconds without any typing or refocus, the animation stops, parked at full size. Output from a program doesn't count as activity here.

- Only the focused pane of the active window animates. Every other cursor is parked at full size.

- A parked cursor doesn't draw any frames.

- When a program hides the cursor, the cursor isn't drawn at all.

- The character under a block cursor must be readable in every theme, in dark and light mode.

- The cursor can join the text scrim and the text outline. By default it joins the outline and not the scrim.

## Goals

- The cursor moves the way the text around it moves. It moves smoothly, and it never jumps in size or place.

- The cursor clearly shows where typing will go, without a hard on-off blink.

- There isn't any cost while nothing is happening. An idle terminal on a laptop shouldn't keep a core busy to animate a cursor.

### Non-goals

- SilkTerm doesn't change how the shell edits a line. Insert and overwrite belong to the shell's line editor, and a terminal can't force them.

- The slide itself doesn't have any settings. Its speed and catch-up are source constants.

## Design

### The slide

The cursor slides toward its target column with an exponential ease. A newline snaps it, so a slide never runs diagonally across the screen.

- The time constant shrinks the farther the cursor trails, so a paste or a fast burst catches up, while a move of one cell still gets the gentle slide.

- A hard cap limits the drawn cursor to 8 cells behind its real column.

- The animation keeps running through the slide. An earlier version drew the cursor as a solid full block while it slid, which made its size jump on every keystroke.

### Shape and animation

- `cursor.size.width` is the width in percent from the left. `cursor.size.height` is the height in percent from the bottom. A bar is about 15 wide, and a block or underline is 100 wide. Together they can make any shape, and they replaced an older shape setting.

- `cursor.blink` turns the animation on or off. When it's off, the cursor stays still.
	- Before 2026-10-09 that was `cursor.animation: none`. On launch, that line is rewritten as `blink: false`, and `none` is still read as off.

- `cursor.animation` is `phase`, `pulse_vertical`, `pulse_horizontal`, or `pulse_both`.
	- `phase` is a smooth cosine fade between on and off.
	- A pulse starts as a single-pixel line in the middle of the cell, grows to full size, stays there a moment, shrinks back, disappears for a moment, and then starts again.
	- Every style fits one cycle into `cursor.blink_rate_s`, from one peak to the next. The default is 1000 ms.
	- It was `cursor.blink_rate_ms` before 2026-10-09, and that counted half a cycle, so 500 meant a second. On launch, the old line is renamed and its value converted, so nothing blinks faster or slower.

- Frames that only change the cursor skip reshaping the text, so an animating cursor doesn't peg the CPU.

### Pausing and parking

The state machine is `PauseState` in `pane.rs`. Its rule took several attempts to get right. A pause always waits for the largest point in the cycle, and a resume always starts from that same point.

- Typing pauses the cursor. On input, the cycle runs on at normal speed until the cursor reaches full size, and then it stays there. It resumes from full size once typing has stopped for `cursor.animation_resume_s`.

- A keystroke's echo counts as typing, but only if it comes right after the key. Anything later comes from the program. So after Enter is pressed, a whole build's worth of output isn't counted as typing.

- Output parks the cursor only while it is being written. When it stops, the animation picks up without any delay.

- A refocus of the window, tab, or pane resumes at once from the top of the cycle.

- The long stop is measured from the last input or refocus, rather than from the last time the cursor moved. A clock in a prompt, or any full-screen program on its own timer, moves the cursor every few seconds, and that isn't allowed to keep it animating. `cursor.animation_idle_stop_s` is 60 by default, and 0 means never.

- Every pane other than the focused pane of the active window is parked, through the same machine.

- A parked cursor doesn't draw any frames. Parked idle is about 0.2% of a core, against about 14% with the pulse running. An unfocused window's panes all park, so the window doesn't draw any frames at all.

- The old always-animating mode is behind the source constant `CURSOR_ANIM_CONTINUOUS`. `FREEZE_UNFOCUSED_BLINK` rolls back the parking of unfocused panes.

### Waking on time

A parked cursor that is due to resume sets its wake time while the frame is drawn. The event loop reads every pane's wake time, including the cursor's, from one list after the frame rather than before it. When they were read before drawing, a cursor that parked during the frame didn't have any wake time at all, so it waited for some unrelated event.

### Hidden cursors

Whether the cursor is shown and what shape it has are 2 separate things in the engine, and both are read. A program that redraws its whole display hides the cursor first, redraws, then puts it back and shows it again. When only the shape was read, a second cursor was drawn wherever the redraw left it, which on Windows is the bottom-right corner. A hidden cursor isn't drawn and doesn't cost any frames.

### Drawing order and legibility

- The cursor is drawn after the scrim is composited and under the crisp text, so the scrim never covers it.

- The cursor draws into the scrim's source before the blur when `cursor.scrim` is on, so its halo doesn't cost anything extra. `cursor.outline` works the same way for the outline.

- A block cursor is a second background. It's drawn as a plate under the glyph, and the glyph keeps its own color, so the text on it has to clear the contrast floor against the plate. See the [Themes](20260930-150458_themes.md) design doc for the plate's strength in light and dark mode, and for the cursor colors.

## Alternative ideas

### Unconsidered

- Smooth vertical cursor movement. Only the horizontal slide exists. It was raised in "The Notorious "Bouncing Shadow in Wobbly Nano" bug" (Opened 20260707-182523).

- A gold pulse from the cursor when a command returns to the prompt, stronger the longer the command ran. It's Effect 2 of "Rolling epic "GPU FX"" (Opened 20260714-091630).

### Rejected

- Insert and overwrite modes with a cursor for each. A terminal can't put the shell's line editor into overwrite mode. Backlog: "Allow toggling from default "Insert" mode, to "Overwrite"" (canceled).

- A lower frame rate for the idle cursor. The floor for smooth motion is 30 frames a second. Parking the cursor fixed the cost instead. Backlog: "Epic 1n6fydv: Reduce CPU and GPU resource usage", item 2.3.

- Freezing inactive windows unless they have output. That was folded into parking the unfocused panes, since a visible window with output should keep drawing. It's from the same epic.

### Superseded

- `cursor_animation_input` with a "continuous" mode that never paused. Pause is the only mode now. Backlog: "Cursor animation immediately resets and starts over on keypresses" (Opened 20260703-211333).

- A wait of 2 seconds before resuming after typing. It's 1 second now. Backlog: "Cursor animation pause: one second, and no wait at all on refocus".

- A fade (`phase`) as the default animation, then a 25%-wide bar as the default shape. The defaults are the up-and-down pulse and a full block. Backlog: "Cursor: new defaults for size and animation" and "New defaults: block cursor, and wallpaper rotation on by default".

- The `cursor_shape` setting. Width and height percentages replaced it. Backlog: "Cursor settings: size as two percentages, plus an animation style".

- Cursor colors #ff88aa, then #eecc88 on #88eecc text. Text was hard to read under the cursor with either one. See the [Themes](20260930-150458_themes.md) design doc.

## Research findings

- The cursor animation was the largest idle cost in the program. A running pulse took about 14% of a core, and about 6% focused against about 0% unfocused after parking.

- A program that moved the cursor every 2.5 seconds kept the old animation running for as long as it ran, since the stop was measured from cursor movement.

## Roadmap

- The Cursor tab has 3 planned "Animation pauses on" checkboxes. They're for loss of window focus, loss of pane activity, and input inactivity. The first 2 are source constants today. Backlog: "Settings dialog" (Opened 20260719-085918).

- A per-program list that turns the cursor animation off while that program runs. It could be done per pane. Backlog: "Config file: For each feature listed below, allow user to list programs" (deferred, Opened 20260708-115155).

- The 4 window wakes that are read after the frame don't have a test yet, and a cursor that resumes on time still needs a look on screen. Backlog: "A cursor blink or fade can wait for an unrelated event" (2026092821452948).
